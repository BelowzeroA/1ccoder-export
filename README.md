# 1CCoder — клиентское приложение

Настольное приложение 1CCoder для Windows: ИИ-агент для разработки на 1С:Предприятии. Здесь —
весь клиент: интерфейс, агент и его навыки, инструменты работы с информационной базой, профили,
управление MCP Toolkit, автоматический режим. Сервер (вход, доступ к модели, учёт кредитов,
телеметрия, обновления) — ваш; что он должен уметь, описано в `BACKEND-CONTRACT.md`.

Приложение построено на [opencode](https://github.com/anomalyco/opencode) (MIT) и сохраняет его
структуру: монорепозиторий на Bun, Electron-оболочка в `packages/desktop`.

## Что где

| Каталог | Что там |
|---|---|
| `packages/desktop` | Electron-приложение. `src/main` — главный процесс: связь с сервером (`llm/`), профили (`profiles/`), операции с базой и навыки агента (`infobase/`, `skills/`), MCP Toolkit (`mcp/`), телеметрия (`telemetry/`), обновления. `src/renderer` — экраны входа, профилей, кредитов. `resources` — то, что едет в установщик (ниже) |
| `packages/app`, `packages/ui`, `packages/session-ui` | Интерфейс сеансов, общий с opencode, с доработками 1CCoder |
| `packages/opencode` | Движок агента, который приложение запускает отдельным процессом |
| `packages/desktop/resources` | Собранный плагин агента `1ccoder-plugin.mjs`, `v8pack-cli.mjs` (работа с контейнерами `.epf`/`.cfe` без платформы), шаблоны обработок, MCP Toolkit, навыки работы с табличными документами |
| `EXPORT-README.md`, `BACKEND-CONTRACT.md`, `RELEASE.md`, `THIRD-PARTY.md` | Этот файл, контракт сервера, порядок выпуска, сторонние компоненты |

## Что нужно для сборки

- Windows 10/11 x64; 10+ ГБ свободного места на диске с `TEMP` (кеши Bun и Electron по умолчанию
  тоже в профиле пользователя: при нехватке места перенаправьте `TEMP`/`TMP` и `BUN_INSTALL`).
- **Bun ровно той версии, что указана в `package.json` (`packageManager`)**, сейчас 1.3.14. Более
  новая версия падает при сборке. Установка нужной: `& install-bun.ps1 -Version "1.3.14"` (параметр
  скрипта, а не переменная окружения).
- Node.js в `PATH` (у нас собирается на 24.x): интерфейс собирается под Node, не под Bun.

## Адреса вашего сервиса

Перед первой сборкой скопируйте `packages/desktop/.env.example` в `.env.production` и
`.env.development` в том же каталоге и укажите адреса своего сервиса и контакт поддержки.
Значения вшиваются в приложение при сборке; без них сборка останавливается с ошибкой.

| Переменная | |
|---|---|
| `ONECCODER_SERVER_URLS` | Адреса сервиса через запятую, в порядке предпочтения. Обязательна |
| `ONECCODER_SUPPORT_CONTACT` | Контакт поддержки для сообщений пользователю. Обязательна |
| `ONECCODER_UPDATES_URL` | Каталог обновлений; по умолчанию первый адрес + `/updates` |

Переменные окружения с теми же именами важнее файлов — так удобно задавать их в CI.

## Сборка и запуск

```powershell
bun install                      # из корня репозитория
cd packages\desktop
bun run dev                      # приложение в режиме разработки; первый запуск — 3–5 минут
```

Установщик:

```powershell
cd packages\desktop
$env:OPENCODE_CHANNEL = "prod"                       # "beta" — бета-канал
$env:NODE_OPTIONS = "--max-old-space-size=4096"      # иначе сборка интерфейса упирается в память
bun run build                                        # плагин, ripgrep, движок агента, electron-vite
bun x electron-builder --win --publish never --config electron-builder.config.ts
```

Результат — `packages\desktop\dist\1ccoder-setup-<версия>.exe`, `.blockmap` и `latest.yml`. Как их
подписать и выложить — `RELEASE.md`.

Если сборка необъяснимо падает по памяти, сначала проверьте, не висят ли лишние процессы `node`.

## Тесты

```powershell
cd packages\desktop
bun typecheck
bun test src/main src/renderer/profiles ./endpoints.test.ts
```

Под `bun test` адреса сервиса берутся из `packages/desktop/.env.test` (примерные, ни один тест к
ним не обращается). Известная особенность: одна ошибка `No such built-in module: node:sqlite` —
модуль телеметрии использует встроенный SQLite Node, которого нет в Bun; на остальные тесты она
не влияет.

Несколько тестов проверяют код на настоящих файлах 1С и без них пропускаются. Чтобы их запустить,
укажите пути в `packages/desktop/.env.test.local` (файл не попадает в Git):

| Переменная | |
|---|---|
| `DUMP_BP30`, `DUMP_UT11`, `DUMP_KA2` | Каталоги выгрузки конфигураций в файлы: Бухгалтерия предприятия 3.0, Управление торговлей 11, Комплексная автоматизация 2 |
| `V8PACK_FIXTURES` | Каталог с `MCP_Toolkit.epf` и расширением `OneMCP.cfe` |

Тест `src/main/product-names.test.ts` следит, чтобы в коде не появлялись названия клиентов,
профилей и баз: запрещённые слова в нём хранятся хешами. Добавить своё слово — команда в
комментарии к тесту.

## Что нужно у пользователя

- Windows 10/11.
- Платформа 1С:Предприятие 8.3 или 8.5 и информационная база (файловая или серверная). Путь к
  платформе, база, пользователь и рабочий каталог задаются в **профиле** в приложении.
- Для работы с данными базы приложение запускает в ней MCP Toolkit — внешнюю обработку из
  поставки (`resources/toolkit`). Пользователю 1С нужно право открывать внешние обработки. Флажок
  «Защита от опасных действий» у пользователя приложение снимает само перед запуском, если у
  пользователя есть право «Администрирование»; иначе подскажет, где его снять.

## Где менять поведение агента

| Что | Где |
|---|---|
| Системные указания агенту | `packages/desktop/src/main/skills/agents.ts` |
| Навыки (тексты, которые агент читает по задаче) | `packages/desktop/src/main/skills/content.ts`, пакеты конфигураций — `skills/packs/` |
| Инструменты `1c_*` | `packages/desktop/src/main/infobase/plugin.ts` |
| Проверка записи в базу, подтверждения | `packages/desktop/src/main/infobase/writes.ts` |

После правки кода плагина или навыков пересоберите плагин: `bun ./scripts/build-v8pack-cli.ts` в
`packages/desktop` — `bun run dev` сам его не пересобирает, а приложение устанавливает агенту то,
что лежит в `resources/`.
